**Verdict for unattended-live**: **NOT YET**. Three blockers stand:

1. **Cockpit-BFF external escalation watcher** (cockpit-team) — the spec mandates a watcher external to Kora's container that auto-escalates kora_control commands to L4 on SLA breach. Kora's runtime correctly surfaces *that the watcher is unreachable* via the `escalation_watcher_liveness` health subsignal + the FE "Control escalation unavailable — use manual L4" panel banner. Until cockpit-team ships the watcher, every operator-issued STOP-KORA L1/L2/L3 requires a human to manually fire L4 if Kora doesn't acknowledge within SLA.
2. **CC#1's KR-P2-INT-TESTS** — Subsection 2's staging items (idempotency E2E, PITR simulation, STOP-KORA L1-5, cost pause, poison-ticket) are still in-flight at CC#1. The Kora-runtime side has unit + lifecycle test coverage; the integration tests that exercise *the seams* between substrate + runtime + cockpit are the missing layer.
3. **Token-rotation dry-run** — the runbook lands (PR #86); the actual dry-run has not been performed. Procedural; not a code task.

The two IsoKron-team cold-archive sweepers are NOT v1 blockers — the live `kora_control` + `kora_operation_ledger` tables are unbounded but write rates are low enough that 90 days of growth is manageable. Defer.

The two Kora-runtime small gaps (retry_ceiling raise-site + per-level SLA pinning) are deferred to follow-up buckets per Rule-3 — they require coord with cockpit-team to settle the Runtime Contract manifest format. No ST PR opened in this bucket.

## Conclusion — answer to "what's still in the way of unattended-live?"

**Hard blocker** (no operator workaround): **Cockpit-BFF external escalation watcher**. Until cockpit-team ships it, every L1/L2/L3 STOP-KORA requires a human to manually escalate to L4 on SLA breach — defeats the unattended-live premise.

**Soft blockers** (operator effort, no code): pre-launch staging drills (token-rotation dry-run, PITR drill, KR-7 drill, STOP-L4/L5 drills) + CC#1's KR-P2-INT-TESTS bucket landing the idempotency E2E + STOP-KORA L1-5 E2E + cost-pause E2E + poison-ticket E2E coverage. These don't need Kora-runtime work.

**Deferrable** (low-impact gaps): cold-archive sweepers (IsoKron-team, defer until table growth surfaces it); `blocked_needs_operator` cockpit actions (cockpit-team, manual SQL works until shipped); `retry_ceiling` raise-site (Kora-runtime, one small bucket).

**Clean** (zero gaps): everything in §9.1 / §9.2 / §9.5 / §9.6 / §9.7 / §9.8 except the items called out above. The §9 machine is shipped + tested + documented end-to-end.

**Bottom line**: Kora's runtime is complete enough that the gating concern for unattended-live is now the external escalation watcher (cockpit-team) + the staging drills (operator) — NOT any Kora-runtime work.
